# LifePlan — Fitness, Health & Faith (formerly FitPlan)

Static SPA deployed to GitHub Pages: https://melanialani.github.io/personal-trainer/

Real website in active use (not a Figma prototype): logic must be correct and robust, and changes must not break users' saved data.

## Stack & commands
- Vite 6 + React 18 + TypeScript (strict) + Tailwind v4 + Recharts + lucide-react.
- `npm run dev` → http://localhost:4007/personal-trainer/ (port 4007 is fixed, `strictPort`).
- `npm run build` (runs `tsc --noEmit` first) · `npm run typecheck`.
- Deploy: push to `main` → `.github/workflows/deploy.yml` builds and publishes `dist/` to Pages.

## Rules
- No backend. All data lives in `localStorage` key `fitplan:data` as one `AppData` object (`src/types.ts`).
  Any new field must get a default in `normalizeData` (`src/lib/storage.ts`) so old backups/imports keep working.
  Per-device UI state uses `fitplan:theme` and `fitplan:nav` (not in backups). Never rename the `fitplan:*` keys or
  the backup app id `fitplan` (would lose saved data); the old name stays internal.
- Routing uses `HashRouter` (Pages has no SPA fallback). Vite `base` is `/personal-trainer/`.
- Read/write data only through `useAppData()` (`update`, `upsert`, `remove`) in `src/store/AppDataContext.tsx`.
- Deletes and destructive actions go through `useConfirmDelete()` / `useConfirm()`; never `window.confirm()`.
- Modals use `shared/components/Modal` (no outside-click / Escape close).
- Reuse shared components in `src/shared/components` and food UI in `src/features/foods` (FoodPicker, FoodRow, ServingForm, AddFoodModal).
- Generic helpers: `lib/math` (round, clamp, sum, average), `lib/format` (display strings, pluralize), `lib/date`; shared hooks in `src/shared/hooks` (`useProfile`, `useBodyWeightKg`, …); JS/chart colors in `src/shared/theme.ts`. Check these before writing a helper.
- Calculations live in `src/lib` (calc, mealPlanGenerator, workoutGenerator) — keep UI files free of formulas.
- Static datasets live in `src/data` (foods, meal templates, exercises, activities, medicines, care guides, diet guides, cycle rules, Bible books, verse topics, lectionary, reflections, prayers, rosary, vaccines, child supplements, milestones, parenting stages, WHO growth standards). Meal templates must only reference existing food ids.
- Bible texts are static JSON in `public/bible/` (generated by `scripts/build-bible.mjs`; never hand-edit). Only bundle texts whose license allows redistribution (no TB/LAI, no Puji Syukur/Madah Bakti lyrics).
- Online food search uses Open Food Facts (`src/lib/openFoodFacts.ts`); search only on submit (rate limit ~10 req/min).
- UI text and code in English, except food names and serving labels in `src/data/foods.ts` / meal template titles, medicine/care-guide content in `src/data/medicines.ts` / `careGuides.ts`, prayer/rosary content in `src/data/prayers.ts` / `rosary.ts`, and parenting content in `src/data/vaccines.ts` / `childSupplements.ts` / `milestones.ts` / `parentingStages.ts`, diet guides in `src/data/dietGuides.ts`, cycle messages in `src/data/cycle.ts`, verse topics in `src/data/verseTopics.ts`, liturgical day names in `src/lib/liturgicalCalendar.ts` / reading labels in `src/lib/lectionary.ts` and reflections in `src/data/reflections.ts` (Indonesian, by request). Reflections are written for the app (labeled as not official Church texts) and must follow the day's actual readings. Prayer texts must be verified Catholic (KWI) wording — never invented; the only exception is the `personal` category (Doa Pribadi: personal prayers written on request, labeled as not official, no sources). Child-health content (vaccines, doses, growth) must come from official sources (IDAI, Kemenkes, WHO, CDC) cited in the data file — never invented.
- `src/data/growthStandards.ts` is generated by `scripts/build-growth.py` from WHO tables; never hand-edit.
- `src/data/lectionary.ts` (reading citations only) is generated by `scripts/build-lectionary.py`; never hand-edit. Liturgical day logic lives in `src/lib/liturgicalCalendar.ts` (Indonesian calendar) and its keys must match the lectionary keys. Reading text always comes from the bundled Bibles (`lib/scripture.ts` maps Lectionary/Hebrew verse numbers to the bundled English numbering).
- Light + dark theme: use `bg-surface` (not `bg-white`) for cards/inputs, add a `dark:` shade to colored text, and keep text contrast ≥ 4.5:1 in both themes (see Theme in `docs/architecture.md`).
- Colors: `brand-*` = the current module's accent (remapped per nav group via `data-accent`); use `tone` on `Card` / `StatTile` (`shared/tones.ts`) to mix colors. Form modal footers use `ModalActions`. Bottom-pinned bars hide with `useKeyboardOpen()`. No `backdrop-blur` on sticky/fixed bars. See Colors & UI conventions in `docs/architecture.md`.

More detail: `docs/architecture.md`.
